Visualize kit

Every block a page can start from, live, with its markup one click away. Blocks are defaults, not rules: change them, combine them, or build a new one from the same tokens.

A page links nothing local: inline pastes kit.css and kit.js into it. Libraries load from a CDN only on pages that use them, and each block that needs one keeps its content as text first, so the page still reads offline. The demos below use small, unrelated subjects on purpose: a block fits a shape of content, not a topic.

Text

Callout

A point the reader must not miss: a caveat, a rule, a result. data-tone: info (default), ok, warn, bad, tip. A bold lead-in takes the tone color.

Note. Sunlight takes about 8 minutes 20 seconds to reach Earth, so the Sun you see is the Sun of 8 minutes ago.

Holds. Each git commit's hash covers its parent's hash, so rewriting an old commit changes every hash after it.

Careful. In floating point, 0.1 + 0.2 is 0.30000000000000004. Keep money in whole cents.

Breaks. A regex with nested quantifiers, like (a+)+$, can take exponential time on a long input that does not match.

Tip. Dough has proofed enough when a floured fingertip dent springs back slowly.

Stat tiles

Key quantities a reader should remember. The number leads, the label says what it counts. key marks the one that matters most.

27.3 daysfor one orbit around Earth

Glossary

Terms the page relies on, defined once. Stacks on narrow screens.

Cache hit
The response comes from a stored copy, with no trip to the server.
ETag
A tag for one version of a resource, so a client can ask "has this changed?"
max-age
How many seconds a stored response stays fresh.

Term tooltip

Jargon defined in place. Shows on hover, focus or tap; Escape hides it. Without scripts the definition prints in brackets.

Sourdough rises because of its starter: wild yeast living alongside lactobacilli.

Data

Table

Rows of facts with the same fields. Wrap it in .scroll so a wide table scrolls in its own box (kit.js adds the wrapper if it is missing). .num right-aligns a numeric column; data-tone or data-c on a cell tints it.

Comparison

A trade-off or a before and after. Two to four columns that stack on narrow screens. data-tone on a column colors its border and heading, for when one side is the better one; data-c colors the border only.

Array

  • Reads item i in one step
  • Inserting in the middle shifts every later item
  • Items sit side by side, so the CPU cache helps

Linked list

  • Reaching item i walks i links
  • Inserts in one step once you hold the node
  • Every node carries a pointer, so more memory

Proportion bar

Shares of a whole. Each item's number goes in <b>; kit.js draws the bar and adds percentages unless the numbers already are. Colors follow the series order, or set data-c (1 to 8) or data-tone.

Chart

Numbers whose shape matters: a trend, a comparison, a spread. The table is the data and the fallback; Chart.js draws from it and the table moves under a Data toggle. First column: labels (x values for scatter). Other numeric columns: one series each; a text column is not a series, and the first one names each point in tooltips. A line chart whose labels are all plain numbers (years, sizes; no units) gets a true-to-scale x axis. Color a series with data-c or data-tone on its th; otherwise colors follow column order. All-integer data gets whole-number ticks. data-type: bar (default), line, pie, doughnut, scatter. Also data-x and data-y (axis titles: label axis, value axis), data-log ("y", "x" or "x y"), data-stacked, data-horizontal. Anything else: kit.chart() under Page scripts. It only draws: put its canvas in <div class="chart-box"> for the kit's height, and keep the numbers as text beside it (a table in .scroll, or the caption) for readers without the library.

2x2 matrix

Items placed on two axes. Children in order: top left, top right, bottom left, bottom right. Axes grow up and to the right; name them with data-y and data-x.

Flow

A sequence or pipeline. Up to four stages run across a wide column, five or more wrap in rows of three, and a narrow column stacks them downward. Branches

A decision that splits into paths. Optional start <p>, one <section> per path, optional end <p> where they meet. Paths sit side by side, or stack with "or" between them. data-tone on a path colors its border and heading; data-c colors the border only.

A cached copy exists: is it still fresh?

Fresh

Younger than its max-age. Serve it from the cache with no request at all.

Stale

Ask the server with the ETag. A 304 reuses the copy; a 200 brings a new one.

Cells and fields

Layout in memory or on disk. .cells is a grid of --cols columns; .label starts a row; data-c or data-tone fills a cell, solid when empty, tinted when it holds text. .fields is one record, each field as wide as --w; on narrow screens it turns into a list, and a bar under each row keeps its share.

Small multiples

Cases or scenarios side by side: one mini figure per case, drawn the same way, so the eye reads only what differs. Each case is a <figure> in .cases; any kit block works inside. The caption says the outcome in words, led by a .tag for the status, so color is never the only cue. Three to six cases; they wrap to fit.

Before and after

Two states of one figure, to show what a change does. The radio pair in .ba-pick picks the state; .ba-stage holds the two states in the same order, stacked in one spot so nothing jumps. No script: it works by CSS alone, and arrow keys switch. Each state's data-label names it in print, where both show. For two things side by side, use Comparison instead.

Annotated figure

A picture with numbered pins and a key. The art is inline SVG, an inline image or HTML; pins sit at --x, --y percentages of it. SVG parts take token colors from classes: .box, .wire, .hi, .tint, .ink, .muted (see Helpers).

UI mock

A screen, to show what a user sees. data-frame: browser or phone; data-url shows the address on either. Write the screen in HTML inside .mock-screen; kit blocks work inside it, and its controls stay out of the tab order. For a series of screens, give each .mock-screen the same aspect-ratio (say 9 / 16 for a phone) so heights match.

Mermaid

States, protocols, sequences, entity relations: diagrams whose layout a tool should compute. The source is the content and stays readable if Mermaid cannot load. Prefer a hand-built block when the layout itself carries meaning. A diagram much wider than a phone scrolls sideways there; short edge labels keep it narrow.

Code and math

Code

A snippet to read or reuse. language-* on <code> turns on highlighting; the caption names the file. A bare <pre><code> becomes this block too. Copy button included.

Annotated code

Code where a few lines carry the idea. Each note names its lines in data-lines ("3", "5-6"); the lines get marked and numbered. Hovering a note lights its lines.

Code diff

What a change does to code. Add diff to a .code figure and start each line with + (added), - (removed) or a space (kept); kit.js tints the lines, and the signs stay as text, so print and color-blind readers still see them. Use the code's own language-*, not language-diff. Keep a few kept lines around each change for context.

Formula

TeX in div.math (display) or span.math (inline), rendered by KaTeX. Offline, the TeX shows as is. Escape < and & as entities. Display math wider than its column scrolls; break long math into aligned rows (\begin{aligned}) so a phone shows it whole. The second formula below scrolls on a phone.

A = P\left(1 + \frac{r}{n}\right)^{nt}

With P = 1000, r = 0.05 and yearly compounding, ten years give A \approx 1629.

(x + y)^n = \sum_{k=0}^{n} \binom{n}{k} x^{n-k} y^k = x^n + n x^{n-1} y + \binom{n}{2} x^{n-2} y^2 + \cdots + y^n

Terminal

A command and what it printed. Commands go in span.cmd, which adds the prompt; the rest is output.

Interactive

Tabs

Alternatives a reader picks one of: languages, platforms, levels of detail. One section[data-tab] per tab. Arrow keys move between tabs. Without scripts, and in print, every section shows under its name. A row wider than the column scrolls, with a shadow at the edge that hides more; on a phone that starts at about four tabs.

Collapsible

Detail most readers can skip: a derivation, an edge case, the long version.

Why is the sky blue?

Air molecules scatter short wavelengths far more than long ones. Blue light bounces around the whole sky and reaches your eye from every direction, while most red light passes straight through.

Popover note

A footnote or aside the reader opens in place. A button.fn with popovertarget opens the aside.pop[popover] with that id; a click outside or Escape closes it. No script. Give the button an aria-label ("Note 1"); put the aside right after the paragraph, since that is where it prints, and start its text with the same number. It sits under the button where the browser can anchor it, else mid-screen. For one-word definitions, Term tooltip is lighter.

Sunlight takes about 8 minutes 20 seconds to reach Earth.

1. The Sun is 149.6 million km away on average; at 299,792 km/s that is 499 seconds.

Step-through

A mechanism the reader follows one stage at a time. One <li> per step in .stepper-steps. Anything in .stepper-stage with data-at lights up on the steps it names ("2", "1 4", "3-"): kit boxes take the accent fill, and the rest dims. Dimmed parts are translucent, so lines drawn behind them show through. data-reveal on the stepper hides unlit parts instead. Arrow keys step. Print shows every step and every part.

  1. ClientSYNhere is my starting number
  2. ServerSYN-ACKgot it, here is mine
  3. ClientACKgot yours too
  1. The client sends SYN with a random starting sequence number.
  2. The server answers SYN-ACK: it acknowledges the client's number and sends its own.
  3. The client acknowledges the server's number with ACK.
  4. Both sides now know where the other starts counting, so the connection is open. It cost one round trip.

Scrub bar

A step-through with five or more steps, where a reader wants to jump or replay. data-scrub on .stepper adds a slider over the steps and a Play button that moves one step every 1.8 seconds and stops at the end; any other control stops it. It never plays on its own. Print and no-script readers get every step, as in Step-through.

Playground

How a knob changes an outcome. Range inputs in .controls, results in .out. Put the <output> after the input, so the label names the slider; kit.js keeps it in sync (data-unit adds a unit). Give each input a name and each result a data-out, and compute them with kit.model as in Reactive sentence. The markup holds the default values as text, so print and no-script readers get true numbers; make the default the real value.

$1,629from $1,000, compounded yearly
$629of it is interest

Reactive sentence

A claim whose numbers the reader can push. Inside .reactive, each input has a name and an aria-label, and every number that follows from it has data-out. One page function, kit.model(box, values => outputs), takes the inputs by name (or id) and returns text for each data-out; a returned number also sets --name on the box, for a figure to use. The markup holds the default values as text, so print and no-script readers get a true sentence; make the default the real value. One to three inputs.

Driving nonstop to the Moon at 100 km/h takes 160 days.

Linked highlight

Prose that points at parts of a figure. Give a word in the text class="ref" and a data-ref name, and give the matching parts of the figure the same data-ref. Hovering or focusing either lights every match: kit boxes take the accent fill, other elements an outline, SVG shapes a thick accent line. The words are in the tab order; the figure parts only respond to hover. The prose must make sense alone, since that is what print and screen readers get.

Self-check

A question that tests what the page taught. Options are buttons, the right one has data-correct; the answer sits in a <details> that opens on a right pick. Options are optional: a question and its answer work alone.

Why must the list be sorted for binary search?

Show answer

In a sorted list everything left of the middle is smaller and everything right of it is larger, so one comparison tells you which half cannot hold the target.

Predict, then reveal

A Self-check asked before the answer, for a result that surprises. A guess makes the reveal stick. .check.predict holds a fieldset of radio choices (one has data-correct), each with a .why line that shows once it is picked, then a .reveal with the figure or answer that shows after any pick. It works by CSS alone; kit.js adds a spoken verdict. Start each .why with "Right" or "No", so the verdict is in words, not only color. Print shows every reason and the reveal.

With no air, a 1 kg ball and a 10 kg ball drop from 100 m. Which lands first?
4.5 sto fall 100 m, for any mass

Air is what makes a feather slow. On the Moon, Apollo 15's David Scott dropped a hammer and a feather, and they landed together.

Build your own

Custom block

When no block fits the shape, build one. Same box (var(--card), var(--border) solid var(--line), var(--radius)), same type sizes, colors only from tokens, tints from color-mix() of tokens. Inline SVG for geometry, styled with tokens; its text shrinks with the viewBox on a phone, so lay out labelled spans as an HTML grid, or put a wide SVG in .scroll with a min-width. Stack it at the kit's narrow breakpoint, @container (max-width: 30rem), so it reflows where kit blocks do. Text on a tint: --text on up to 24% of a --cN mixed into --card or --bg passes in both themes; --muted on a tint does not. Put its CSS in a page <style> after the kit.

The only colors a page uses. Each switches with the theme. --c1 to --c8 tell series apart; the tones carry meaning; -soft versions are backgrounds for text. --shadow is a see-through dark for shadows and scrims that stays dark in both themes.

Helpers

Small pieces any block can use. .tag labels a thing (color with data-c or data-tone). .legend keys colors. .key highlights the box that matters. .note is a small aside under a block. .scroll gives wide content its own sideways scroll. .nowrap keeps a short span on one line, such as a CLI flag in inline code. A custom box that uses var(--box, var(--card)) and var(--box-line, var(--line)) picks up .key too. In inline SVG, classes color shapes from tokens and leave stroke width to the shape's stroke-width: .box (card fill, strong line), .wire (line only, data-c or data-tone recolors it), .hi (accent), .tint (a light fill of data-c or data-tone with its color as the line), .ink and .muted (text).

Page scripts

For a custom visual that draws with JavaScript. Put the script after kit.js. kit.color('accent') returns a token as hex for the current theme; kit.color('accent', 'light') for the light one, which a canvas can use to redraw on beforeprint, since print is light (kit charts do this already). kit.model(box, fn) wires a Reactive sentence, and works for a Playground too. kit.load('chart' | 'mermaid' | 'katex' | 'hljs') loads a library once. kit.chart(canvas, color => config) draws any Chart.js chart and redraws it on theme change. Listen for kit:theme on document to redraw anything else. A script that shows hidden content of its own (a picker, a panel) dispatches document.dispatchEvent(new Event('kit:shown')) after showing it, so Mermaid inside gets drawn; kit tabs, steps and <details> do this already. A page in another language sets window.kitLabels in a script before the kit.js tag, since kit.js reads it once (keys: contents, back, next, step as "Step {n} of {total}", steps, play, pause, copy, copied, right, wrong, data, toDark, toLight), plus lang and dir on <html>.
