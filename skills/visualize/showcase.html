Visualize kit

Every block a page can start from, live, with its markup one click away. Blocks are defaults, not rules: change them, combine them, or build a new one from the same tokens.

A page links nothing local: inline pastes kit.css and kit.js into it. Libraries load from a CDN only on pages that use them, and each block that needs one keeps its content as text first, so the page still reads offline. The demos below use small, unrelated subjects on purpose: a block fits a shape of content, not a topic.

Text

Callout

A point the reader must not miss: a caveat, a rule, a result. data-tone: info (default), ok, warn, bad, tip. A bold lead-in takes the tone color.

Note. Sunlight takes about 8 minutes 20 seconds to reach Earth, so the Sun you see is the Sun of 8 minutes ago.

Holds. Each git commit's hash covers its parent's hash, so rewriting an old commit changes every hash after it.

Careful. In floating point, 0.1 + 0.2 is 0.30000000000000004. Keep money in whole cents.

Breaks. A regex with nested quantifiers, like (a+)+$, can take exponential time on a long input that does not match.

Tip. Dough has proofed enough when a floured fingertip dent springs back slowly.

Key quantities a reader should remember. The number leads, the label says what it counts. key marks the one that matters most.

Glossary

Terms the page relies on, defined once. Stacks on narrow screens.

Cache hit
The response comes from a stored copy, with no trip to the server.
ETag
A tag for one version of a resource, so a client can ask "has this changed?"
max-age
How many seconds a stored response stays fresh.

Term tooltip

Jargon defined in place. Shows on hover, focus or tap; Escape hides it. Without scripts the definition prints in brackets.

Sourdough rises because of its starter: wild yeast living alongside lactobacilli.

Data

Table

Rows of facts with the same fields. Wrap it in .scroll so a wide table scrolls in its own box (kit.js adds the wrapper if it is missing). .num right-aligns a numeric column; data-tone or data-c on a cell tints it.

Comparison

A trade-off or a before and after. Two to four columns that stack on narrow screens. data-tone on a column colors its border and heading, for when one side is the better one; data-c colors the border only.

Array

  • Reads item i in one step
  • Inserting in the middle shifts every later item
  • Items sit side by side, so the CPU cache helps

Linked list

  • Reaching item i walks i links
  • Inserts in one step once you hold the node
  • Every node carries a pointer, so more memory

Proportion bar

Shares of a whole. Each item's number goes in <b>; kit.js draws the bar and adds percentages unless the numbers already are. Colors follow the series order, or set data-c (1 to 8) or data-tone.

Chart

Numbers whose shape matters: a trend, a comparison, a spread. The table is the data and the fallback; Chart.js draws from it and the table moves under a Data toggle. First column: labels (x values for scatter). Other numeric columns: one series each; a text column is not a series, and the first one names each point in tooltips. A line chart whose labels are all plain numbers (years, sizes; no units) gets a true-to-scale x axis. Color a series with data-c or data-tone on its th; otherwise colors follow column order. All-integer data gets whole-number ticks. data-type: bar (default), line, pie, doughnut, scatter. Also data-x and data-y (axis titles: label axis, value axis), data-log ("y", "x" or "x y"), data-stacked, data-horizontal. Anything else: kit.chart() under Page scripts. It only draws: put its canvas in <div class="chart-box"> for the kit's height, and keep the numbers as text beside it (a table in .scroll, or the caption) for readers without the library.

2x2 matrix

Items placed on two axes. Children in order: top left, top right, bottom left, bottom right. Axes grow up and to the right; name them with data-y and data-x.

Branches

A decision that splits into paths. Optional start <p>, one <section> per path, optional end <p> where they meet. Paths sit side by side, or stack with "or" between them. data-tone on a path colors its border and heading; data-c colors the border only.

A cached copy exists: is it still fresh?

Fresh

Younger than its max-age. Serve it from the cache with no request at all.

Stale

Ask the server with the ETag. A 304 reuses the copy; a 200 brings a new one.

Cells and fields

Annotated figure

A picture with numbered pins and a key. The art is inline SVG, an inline image or HTML; pins sit at --x, --y percentages of it.

UI mock

A screen, to show what a user sees. data-frame: browser or phone; data-url shows the address on either. Write the screen in HTML inside .mock-screen; kit blocks work inside it, and its controls stay out of the tab order. For a series of screens, give each .mock-screen the same aspect-ratio (say 9 / 16 for a phone) so heights match.

Mermaid

States, protocols, sequences, entity relations: diagrams whose layout a tool should compute. The source is the content and stays readable if Mermaid cannot load. Prefer a hand-built block when the layout itself carries meaning. A diagram much wider than a phone scrolls sideways there; short edge labels keep it narrow.

Code and math

Code

A snippet to read or reuse. language-* on <code> turns on highlighting; the caption names the file. A bare <pre><code> becomes this block too. Copy button included.

Annotated code

Code where a few lines carry the idea. Each note names its lines in data-lines ("3", "5-6"); the lines get marked and numbered. Hovering a note lights its lines.

Formula

TeX in div.math (display) or span.math (inline), rendered by KaTeX. Offline, the TeX shows as is. Escape < and & as entities. Display math wider than its column scrolls; break long math into aligned rows (\begin{aligned}) so a phone shows it whole. The second formula below scrolls on a phone.

A = P\left(1 + \frac{r}{n}\right)^{nt}

With P = 1000, r = 0.05 and yearly compounding, ten years give A \approx 1629.

(x + y)^n = \sum_{k=0}^{n} \binom{n}{k} x^{n-k} y^k = x^n + n x^{n-1} y + \binom{n}{2} x^{n-2} y^2 + \cdots + y^n

Interactive

Tabs

Alternatives a reader picks one of: languages, platforms, levels of detail. One section[data-tab] per tab. Arrow keys move between tabs. Without scripts every section shows under its name.

Collapsible

Detail most readers can skip: a derivation, an edge case, the long version.

Why is the sky blue?

Air molecules scatter short wavelengths far more than long ones. Blue light bounces around the whole sky and reaches your eye from every direction, while most red light passes straight through.

Step-through

A mechanism the reader follows one stage at a time. One <li> per step in .stepper-steps. Anything in .stepper-stage with data-at lights up on the steps it names ("2", "1 4", "3-"); the rest dims. Dimmed parts are translucent, so lines drawn behind them show through. data-reveal on the stepper hides unlit parts instead. Arrow keys step.

  1. ClientSYNhere is my starting number
  2. ServerSYN-ACKgot it, here is mine
  3. ClientACKgot yours too
  1. The client sends SYN with a random starting sequence number.
  2. The server answers SYN-ACK: it acknowledges the client's number and sends its own.
  3. The client acknowledges the server's number with ACK.
  4. Both sides now know where the other starts counting, so the connection is open. It cost one round trip.

Self-check

A question that tests what the page taught. Options are buttons, the right one has data-correct; the answer sits in a <details> that opens on a right pick. Options are optional: a question and its answer work alone.

Why must the list be sorted for binary search?

Show answer

In a sorted list everything left of the middle is smaller and everything right of it is larger, so one comparison tells you which half cannot hold the target.

Build your own

Custom block

When no block fits the shape, build one. Same box (var(--card), var(--border) solid var(--line), var(--radius)), same type sizes, colors only from tokens, tints from color-mix() of tokens. Inline SVG for geometry, styled with tokens; its text shrinks with the viewBox on a phone, so lay out labelled spans as an HTML grid, or put a wide SVG in .scroll with a min-width. Stack it at the kit's narrow breakpoint, @container (max-width: 30rem), so it reflows where kit blocks do. Text on a tint: --text on up to 24% of a --cN mixed into --card or --bg passes in both themes; --muted on a tint does not. Put its CSS in a page <style> after the kit.

Tokens

The only colors a page uses. Each switches with the theme. --c1 to --c8 tell series apart; the tones carry meaning; -soft versions are backgrounds for text. --shadow is a see-through dark for shadows and scrims that stays dark in both themes.

Helpers

Small pieces any block can use. .tag labels a thing (color with data-c or data-tone). .legend keys colors. .key highlights the box that matters. .note is a small aside under a block. .scroll gives wide content its own sideways scroll. .nowrap keeps a short span on one line, such as a CLI flag in inline code. A custom box that uses var(--box, var(--card)) and var(--box-line, var(--line)) picks up .key too.

Page scripts

For a custom visual that draws with JavaScript. Put the script after kit.js. kit.color('accent') returns a token as hex for the current theme. kit.load('chart' | 'mermaid' | 'katex' | 'hljs') loads a library once. kit.chart(canvas, color => config) draws any Chart.js chart and redraws it on theme change. Listen for kit:theme on document to redraw anything else. A page in another language sets window.kitLabels in a script before the kit.js tag, since kit.js reads it once (keys: contents, back, next, step as "Step {n} of {total}", copy, copied, right, wrong, data, toDark, toLight), plus lang and dir on <html>.
